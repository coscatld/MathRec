# 外层购电候选筛选实验

此目录保存独立实验。原正文、`data/*_v2.npz`、`results_export.json` 和附件工作簿继续使用原结果。

## 运行

在 `CUMCMThesis-master` 目录执行（需要 NumPy、SciPy）：

```bash
python code/check_outer_candidate_selector.py
python code/run_outer_candidate_experiment.py --workers 4
```

本机可用解释器为 `/Users/mingze/miniconda3/envs/deeptutor/bin/python`。默认测试区间为 2025-02-01 至 2025-12-31，共 334 天；四组分别为问题二、问题三、第四问日前版和第四问滚动版。`--start-date`、`--end-date`、`--cases`、`--output` 可用于独立的小规模复现。

## 固定实验设计

每个合法外层决策时点生成以下候选，菜单在查看新实验结果前固定：

1. 现有 28 场景 LP 计划。
2. 同一初态和物理模型下的点预测 LP 计划。
3. 点预测净负荷分别加上 0.25、0.5、1 倍逐时历史场景标准差后生成的 LP 计划；价格点预测保持不变。
4. 日内更新时另加入保持当前剩余有效合同的候选。

标准差由当时同一组历史情景及其权重计算。没有使用当天未来实际负荷，也没有根据这次回测的费用重新选择余量档位。所有候选都是购电计划，实际执行器固定为原主案的贪心储能控制规则。

每个候选在原始同一组历史情景上回放，采用相同初态、权重和终端规则。评分为购电、调整、五倍紧急补购费用，加上 `beta * abs(末库存 - 6000)`；`beta` 是同一历史情景加权平均价格曲线的中位数乘原终端系数。各候选按自身回放末库存计算这一项。第四问的净负荷与价格继续保持原有同日配对，紧急费用逐情景使用对应价格。

零时，候选自身成为原始计划；日内，各候选共享当日已经承诺的零时原计划，调整费始终相对它结算。“不调整”保持最近一次生效的剩余合同，不能将其误写成恢复零时原计划，也不重复收取历次修订之间的差额费用。

回放中合同保持至当日结束，不模拟后续尚未发布的预报或再次修订。因此该评分仍是有限时域估计，不是完整多阶段控制的精确价值。

## 实际费用对照

原主案和候选筛选案从同一问题相同的期初库存出发，分别闭环运行，状态连续传至次日。两案使用同一冻结预测器和相同历史数据获取规则，每到合法时点重新构造当时可用情景；候选筛选案只改变外层采购。

真实账单只含计划、调整和紧急三项，不混入回放终端罚项。报告另列两案末库存，以及用相同系数在评价期终点计算一次库存修正后的费用。滚动回放窗口相互重叠，各次预计改善不能相加称为年度节费。

扩集的评分保证只适用于同一决策状态下、同一个评分函数内的候选比较。独立基线会沿自身状态演化，后续状态可能与筛选策略不同。未来实际账单能否下降必须查看闭环回测，不由这个数学保证推出。

本区间已被原稿开发使用，此次结果应称开发性回测，不能称为未经接触的独立测试或跨年份泛化证据。

## 文件

- `experiment.json`：事前菜单、运行环境、评分规则和四组汇总。
- `checks.json`：独立机制与信息隔离检查结果。
- `audit.json`：四组完整输出的独立费用、物理约束、3340 次最小评分选择与输入哈希审计。
- `测试报告.md`：费用变化、紧急补购、库存及解释边界的中文汇总。
- `*_summary.json`：实际费用分项、末库存、逐月费用和候选选择次数。
- `*_decisions.json`：每个决策点各候选的统一评分与最终选择。
- `*_baseline.npz`、`*_selected.npz`：两案完整逐时执行数组，可重新核算费用和物理约束。
- `smoke/`：正式完整回测之前的两天试运行。

每组汇总记录原始输入和代码的 SHA-256；运行前后检查这些输入未被修改。原方案另行重算，并报告它与原交付数组的差异。
